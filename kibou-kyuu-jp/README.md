# 希望休管理サイト(日本人従業員用・完全独立版)

これは既存の「希望休管理サイト(ベトナム語版)」とは**完全に別の、独立したプロジェクト**です。
リポジトリ(GitHub)もデータベース(Firebase)もすべて新規に作成し、既存のものとは一切共有しません。

## このプロジェクトの特徴

- 日本語UIのみ
- 1か月あたりの希望休の日数制限:**なし**
- 1日あたりの希望休の人数上限:**なし**
- 送信回数:**月1回のみ**(送信後は再送信・編集不可)
- 従業員ページへのアクセスは、管理者が発行する個別リンク(`?name=氏名`)のみ
- 名前を選ぶプルダウンはありません

## フォルダ構成

```
kibou-kyuu-jp/
```

## セットアップ手順

### 1. 新しいFirebaseプロジェクトを作成する

**重要:既存の希望休サイト(ベトナム語版)が使っているFirebaseプロジェクトとは別の、新しいプロジェクトを作成してください。** 同じプロジェクトを使い回すと、データが混ざってしまいます。

1. [Firebaseコンソール](https://console.firebase.google.com/)にアクセス
2. 「プロジェクトを追加」から新しいプロジェクトを作成(例:`kibou-kyuu-jp`)
3. 左メニューの「構築」→「Firestore Database」→「データベースの作成」
   - ロケーションは `asia-northeast1`(東京)などお好きな場所でOK
   - 「テストモードで開始」を選択(あとでルールを上書きします)
4. 左メニューの「プロジェクトの設定」(歯車アイコン)→「マイアプリ」→ウェブアプリを追加(`</>` アイコン)
   - アプリ名は任意(例:`kibou-kyuu-jp`)
   - 表示された `firebaseConfig` の値をメモしておく

### 2. `firebase-config.js` を書き換える

手順1でメモした値を、`firebase-config.js` の該当箇所に貼り付けます。

```js
export const firebaseConfig = {
  apiKey: "実際の値",
  authDomain: "実際の値",
  projectId: "実際の値",
  storageBucket: "実際の値",
  messagingSenderId: "実際の値",
  appId: "実際の値"
};
```

### 3. Firestoreのセキュリティルールを設定する

1. Firebaseコンソール →「Firestore Database」→「ルール」タブ
2. `firestore.rules` の内容をそのまま貼り付けて「公開」

### 4. GitHubリポジトリを作成してアップロードする

1. GitHubで新しいリポジトリを作成(例:`kibou-kyuu-jp`)
2. この `kibou-kyuu-jp` フォルダの中身(フォルダごとではなく中身)をリポジトリの**直下**にアップロード
3. リポジトリの「Settings」→「Pages」→「Branch」を `main` / `/(root)` に設定して保存
4. 数分待つと `https://ユーザー名.github.io/リポジトリ名/` で公開されます

- 管理者用ページ: `https://ユーザー名.github.io/リポジトリ名/admin/`
- 従業員用ページ: 管理者ページで従業員を追加すると、個別リンクが自動生成されます

## 使い方

### 管理者用ページ(`admin/index.html`)

- 月を切り替えて、各従業員の希望休を一覧表示・確認できます
- 「現在の希望者数」は参考表示のみ(上限設定はありません)
- 月ごとに「公開/非公開」を切り替えられます(非公開の月は従業員ページで送信不可)
- 従業員の追加・削除ができます
- 従業員を追加すると、その人専用のリンクが発行されます。「リンクをコピー」ボタンでコピーし、本人に共有してください
- 「Excel出力」ボタンで、現在表示中の月の希望休一覧を `.xlsx` ファイルとしてダウンロードできます
- 送信済みの従業員には表の右端に「取消」ボタンが表示されます。押すとその従業員のその月の送信データが削除され、本人が再度送信できるようになります(いわゆる「送信の復活」機能)
- 表の日付セルを直接クリックすると、その従業員のその日に「管理者が追加した休み」を追加/解除できます(従業員が自分で選んだ休みとは別枠)。色で区別されます:
  - 🔴 赤色:従業員が自分で選んだ休み
  - 🟣 紫色:管理者が追加した休み
  - Excel出力では、従業員が選んだ休みは「×」、管理者が追加した休みは「△」で区別されます
- 従業員が入力した「連絡事項(有給申請など)」は、表の上にある「従業員からの連絡事項」欄にまとめて表示されます

### 従業員用ページ(`employee/index.html`)

- 管理者から共有された個別リンク(`?name=氏名`が付いたURL)からアクセスします
- カレンダーの各日をクリックすると休み希望(×)のON/OFFを切り替えられます
- 管理者が追加した休みには「会社側指定」というラベルが付き、従業員側では編集できません
- 任意入力の「連絡事項」欄があります。有給申請など伝えたいことがあれば入力し、休み希望と一緒に送信できます
- 「送信」は月に1回のみ。一度送信すると、その月は再送信・変更ができません

## データ構造(Firestore)

| コレクション/ドキュメント | 内容 |
|---|---|
| `employees/list` | 従業員名の一覧(配列) |
| `requests/{従業員名}__{年-月}` | 該当従業員・該当月の希望休データ<br>`offDays`: 従業員が選んだ休み(このフィールドがあれば送信済み)<br>`adminDays`: 管理者が追加した休み<br>`note`: 従業員が入力した連絡事項 |
| `settings/monthVisibility` | 各月の公開/非公開設定 |

## セキュリティに関する注意

このシステムは認証機能を持たず、URL(や公開されているFirebase設定)を知っていれば誰でもデータを読み書きできる設定になっています。社内の限られた人にだけURLを共有する運用を前提としています。より厳密に管理したい場合は、Firebase Authenticationの導入をご検討ください。

## 既存プロジェクト(ベトナム語版)との関係

このプロジェクトは既存の「希望休管理サイト(ベトナム語版)」とはリポジトリもFirebaseプロジェクトも完全に分離しています。データが混ざる心配はありません。

もし以前お渡しした「日本人従業員用ページ(既存リポジトリ内の `employee-jp` フォルダ)」を使っていた場合は、今後はこちらの独立版に一本化することをおすすめします。既存リポジトリ側の `employee-jp` フォルダと、管理者ページ内の日本人従業員管理欄は、不要であれば削除して問題ありません(削除方法が必要であればお知らせください)。
